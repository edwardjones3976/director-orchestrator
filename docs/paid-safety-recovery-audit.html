Round 7: atomic acknowledgement and limits

TaskStore.save(..., spend_settlement=(effect_key, evidence)) writes the full acknowledged run (including result and interaction ID), effect and interaction ledgers, and compact settlement row under the same SQLite transaction and CAS. It checks that the task contains the journal's matching run. The caller's CAS version advances only after commit. Provider content never enters the journal. Dispatch and revision use this transaction before charging spend. Initial acknowledgement settles with an unknown charge; reported synchronous cost stays pending in the journal until terminal settlement or restart recovery.

Persistence has one primary attempt and one recovery attempt, a two-second monotonic retry-admission deadline, 250 ms SQLite and process-lock waits, and 100 ms backoff for temporary lock/I/O errors. Stale CAS reloads and merges the acknowledged run, interaction/effect evidence and revision count into the current record; newer fields survive. An owner plan/generation reset refuses restoration. The deadline prevents starting another attempt; it cannot interrupt an operating system I/O call already in progress. This is not a hard wall-clock I/O guarantee.

If persistence remains unavailable, AcknowledgementPersistencePending stops the outer engine without saving FAILED. The durable pre-submit intent remains AMBIGUOUS (an intent with no acknowledgement observation), and its spend reservation remains exposed. No paid request is retried. The response is retained in memory through the bounded attempts; after process loss its content cannot be guaranteed. Existing intent reconciliation is required before further dispatch. This is the explicit durability bound when storage cannot accept a write.

Restart uses the complete task run, so synchronous Grok and Perplexity results never require polling. For pre-atomic journal-only records, Gemini can use its existing provider readback only with a unique durable interaction binding for the same effect, provider, assignment, phase and generation. Grok, Perplexity, and unbound Gemini stop at OWNER_DECISION_REQUIRED without polling or sending. Packet-only evidence continues through authenticated runtime readback.

Atomicity scope is the local SQLite task database only. main.py constructs TaskStore(settings.sqlite_path) and the engine constructs its spend ledger from that store's path. langgraph_postgres.py supplies a separate Postgres control plane, not a Postgres implementation of TaskStore. This change claims no transaction across those databases. A non-SQLite task store or different spend database refuses metered admission, and acknowledgement persistence also fails closed. Supporting another backend requires a backend-native atomic write first.

The adversarial corpus covers all three providers, dispatch/revision, recovery with complete results and verified interaction bindings, transient failure, transaction rollback, stale CAS merge, persistent exhaustion without FAILED or redispatch, legacy journal-only owner holds, Gemini readback, and backend refusal. Python and Docker were not run. The dispatcher owns test execution, site-board verification, contribution checks after its commit, and exact-head review.

Round 8: shared-store refusal and initial unknown settlement

The admission guard now obtains the store with getattr: a missing or mismatched store raises ProviderDailyLimitExceeded before reservation. Four bounds-test fixtures constructed with object.__new__ now supply a real shared-path TaskStore. A regression covers missing/mismatched stores for all three providers. Production construction remains main.py's TaskStore(settings.sqlite_path) passed to the engine, which creates ProviderDailySpendLedger(store.path). This verifies the source wiring, not a live deployment.

Round 7 replaced the initial None charge with reported usage before workload finalization. That populated actual_cost_usd and removed the request from unreconciled() if finalization stopped execution. Dispatch and revision again record None initially. The atomic journal still retains reported cost and stays pending when it differs from that initial charge, so restart recovers the known cost without resubmitting. The existing four failing subtests retain their immediate-unreconciled assertion and now also check SQL NULL, settled timestamp, restart visibility, and recovery of the retained charge.

The failure-injection corpus is retained. Its revision charge-failure counter now accounts for initial unknown settlement followed by terminal known settlement; acknowledgement failure expects None, while terminal failure expects known cost. Atomic rollback, retry limits, stale CAS, privacy reset, persistent exhaustion and no-redispatch assertions are unchanged. These checks were inspected but not run: Python and Docker execution remain dispatcher-owned for this work order.
