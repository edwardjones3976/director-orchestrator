Provider-specific MCP adapters

The nine provider lanes each have a separate local stdio server. Each names one provider and offers its own status and bounded action tool. Grok Bot is an additional, separate desktop contact documented in Grok Bot chat dispatch; it never masquerades as the xAI model API. No generic provider argument or fallback router is accepted.

Administrator contacts

The three project administrators also have separate MCP wrappers named admin-openai, admin-claude, and admin-cursor. Each exposes its own status and consult tool and delegates to the matching provider transport above. These wrappers carry no new assignment, approval, merge, or publishing authority; the project charter and deterministic Director gates remain in force. They never send a prompt to another administrator as a fallback.

An optional admin-crew wrapper collects their readiness and exposes three explicitly named consult tools. It has no generic target argument and no project authority. Calls still pass through the matching individual adapter and its disabled-by-default switches.

Three group wrappers offer named contact tools without a target selector: admin contains OpenAI, Claude, and Cursor administrator consult contacts; providers contains all nine AI provider lanes plus the separate Grok Bot desktop contact; workers contains the six non-admin provider lanes plus Grok Bot. Each group reports contact readiness and forwards a call to the exact underlying adapter. The original credential, activation, spending, and desktop-input gates still apply. Group registration does not grant Director authority.

The separate Researchers wrapper exposes only Perplexity and Firecrawl public search tools and a readiness status tool. It returns the underlying source results to the invoking human or AI client as JSON text and structured MCP content, including the query and provider identity. It does not brief another provider, create an assignment, or assert a research verdict. Its searches retain the original provider switches, credential checks, and daily attempt caps.

Perplexity has a separate official MCP server at https://api.perplexity.ai/mcp. Register it as its own MCP entry with PERPLEXITY_API_KEY supplied through the host environment. Its tools remain Perplexity research calls; they do not route to Grok or Z.ai.

GitHub likewise has an official MCP server at https://api.githubcopilot.com/mcp/. A separate github host entry can read GITHUB_PAT_TOKEN from the environment. Registration alone does not authenticate or authorize repository writes; Director's GitHub workflow and review gates still apply.

These are advisory model calls. They create no Director work packet, production credit, review verdict, assignment, or external effect. Use the Director's existing admission, budget, review and merge paths for project work. MCP host registration alone grants no provider authority.

Readiness and spending

Status calls are free and report booleans only. Action calls refuse by default. Both DIRECTOR_MCP_PAID_CALLS_ENABLED=true and the matching provider switch (for example XAI_MCP_ENABLED=true or CLAUDE_MCP_ENABLED=true) must be present in the server process. Antigravity's read-only lookup uses ANTIGRAVITY_MCP_READ_ENABLED instead. Grok reads XAI_API_KEY and Z.ai reads ZAI_API_KEY or its current-user Windows DPAPI store at call time. The Z.ai key can be imported from standard input with py -3.12 -m provider_mcp.secret_store import-stdin while PYTHONPATH points at the installed adapter directory. Never pass the key on the command line or in chat. Z.ai additionally requires the owner's production activation record digest in ZAI_PRODUCTION_ACTIVATION. The old Z.ai trial ended on 29 September 2026 and is not an available route. Never put a credential value in an MCP registration command or tracked file.

Action input is capped at 24 KB. API model requests disable tools and bound output to 4000 tokens. Native CLIs run in empty temporary workspaces and return bounded output. Receipts are written under ~/.codex/provider-mcp-receipts/<provider>/ outside worktrees. Calls are capped at 40 xAI or 20 Z.ai attempts per UTC day. A repeated input digest refuses instead of silently retrying an ambiguous previous attempt. These limits apply only to this advisory interface; Director's own budgets and ledger remain authoritative for project execution.

Local registration

From the repository root, run each module with Python 3.12. Set PYTHONPATH in each host entry to the absolute repository root, using the host's environment configuration. Register all nine modules as separate MCP servers:

py -3.12 -m scripts.provider_mcp.openai
py -3.12 -m scripts.provider_mcp.claude
py -3.12 -m scripts.provider_mcp.cursor
py -3.12 -m scripts.provider_mcp.xai
py -3.12 -m scripts.provider_mcp.antigravity
py -3.12 -m scripts.provider_mcp.perplexity
py -3.12 -m scripts.provider_mcp.firecrawl
py -3.12 -m scripts.provider_mcp.copilot
py -3.12 -m scripts.provider_mcp.zai

Administrator wrappers are separate modules:

py -3.12 -m scripts.provider_mcp.admin_openai
py -3.12 -m scripts.provider_mcp.admin_claude
py -3.12 -m scripts.provider_mcp.admin_cursor

The combined entry runs py -3.12 -m scripts.provider_mcp.admin_crew.

The group entries run py -3.12 -m scripts.provider_mcp.admin, py -3.12 -m scripts.provider_mcp.providers, and py -3.12 -m scripts.provider_mcp.workers. Set GROK_BOT_MCP_SCRIPT to the absolute path of the separately installed grok_bot_mcp.py adapter in the providers and workers host entries. If the desktop adapter is unavailable, its status reports unconfigured and its tools refuse.

The research-only entry runs py -3.12 -m scripts.provider_mcp.researchers and may be registered as Researchers. Its two actions accept only a public query of at most 500 characters and return results only to the calling MCP host.

For Codex, the official Perplexity remote registration is:

codex mcp add perplexity --url https://api.perplexity.ai/mcp --bearer-token-env-var PERPLEXITY_API_KEY
codex mcp add github --url https://api.githubcopilot.com/mcp/ --bearer-token-env-var GITHUB_PAT_TOKEN

Do not enable paid-call switches merely to test the MCP handshake. Verify initialize, tools/list, and the status tools first. Run py -3.12 -m unittest tests.test_provider_mcp -v to verify protocol separation and default refusals without network calls.
