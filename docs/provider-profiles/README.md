## Authority notice

- These sheets are descriptive. authority_granted is none on every document.
- Documenting a route never authorizes it; the status column is one of authorized, prohibited, or proposed, and default state records explicit enable switches and code blockers rather than credential presence.
- If a sheet and the team operating charter, configuration defaults, or adapter constants disagree, the charter and code win and the sheet is wrong.
- No direct provider-to-provider channel exists. Every exchange between providers is brokered by the Director.
- Values are never recorded: allowlists, keys, tokens, endpoints, paths, and owner identifiers appear only as variable names.

Antigravity has two distinct modes: the roster below mirrors the retained restricted route; its separately owner-authorized team contract admits engineering and independent review only after explicit grants, monetary admission and host qualification. The team mode is default off and not live. See [Antigravity execution modes](antigravity.profile.md#execution-modes).

## How to regenerate

- Edit only the YAML sources in docs/provider-profiles/ (one file per lane plus routes.yaml).
- Render with `PYTHONPATH=src python scripts/render_provider_profiles.py --write --contributor <name> --system <system> --at <ISO-8601 UTC>`.
- Verify with `PYTHONPATH=src python scripts/render_provider_profiles.py --check` and `python -m unittest tests.test_provider_profiles`.
- Never hand-edit a rendered sheet; the check and the tests compare the rendered body with the committed file.
