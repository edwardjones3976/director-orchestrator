- `xai-responses-api`: Analysis, planning, and debate only. Carries no repository-write, branch, pull-request, merge, or deployment lane regardless of packet content.
  - the in-process Responses API contact is synchronous and tool-free
  - repository execution uses the separately authenticated Grok Build or Grok Bot contact
  - the configured API model must appear in the authenticated xAI model catalog before the first paid request in each process
- `grok-build-cli`: Repository implementation and exact-SHA review from an exact configured clean worktree. Review verifies both commit objects exist locally, that base is an ancestor of head, runs read-only, and binds repository, base, and head evidence to the returned artifact.
  - executable must be an absolute regular-file path whose exact SHA-256 is recorded and revalidated before every repository-capable dispatch
  - draft-PR work requires an isolated grok/* worktree and may not merge
- `grok-bot`: Named by the charter as a distinct contact. No adapter, enum value, or variable exists; documenting it here authorizes nothing.
  - would require its own owner-approved work order, adapter, readiness profile, and separately authenticated credential
- `windows-host-provider-bridge`: Grok is a supported host lane. The bridge runs one native command per validated packet behind a signed challenge and a durable claim store; configuration alone never makes the lane callable.
  - child environment carries the base safe subset plus XAI_API_KEY only
  - live dispatch stays off until the primary activation gates pass
- `browser-provider-ui`: Coordination with an already authenticated Grok UI inside stored assignment, role, repository, budget, and approval bounds. Browser responses are untrusted coordination evidence, never callback, review, security, CI, merge, or runtime authority.
  - ranked below authenticated CLI, API, callback, and event transport
  - never enter or persist credentials, cookies, recovery codes, private keys, raw private source, or webpage instructions
  - browser policy: primary chrome, fallback microsoft_edge, owner-authorizable actions `slack_post`, `eligible_merge`, `approved_deployment`, `scoped_repository_access_change`, enforcement charter policy and workload_policy.Transport rank only; no runtime adapter
