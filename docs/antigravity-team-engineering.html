Antigravity team engineering boundary

Default-off implementation; independent review and actual host qualification remain required.

This candidate adds antigravity-team-engineering/v1 beside the existing closed subordinate and debate contracts. The primary-specific LANGGRAPH_PRIMARY_ANTIGRAVITY_TEAM_ENABLED setting defaults to false. Existing Gemini settings and review flags cannot select this contract.

A typed owner-signed TeamGrant binds one v1 work packet, project/repository, commit/tree and review base, full readable manifest with blob hashes, explicit writable and prohibited paths, local command vectors, isolated workspace, native account and Gemini model, complete installation/binding digests, material-author family, expiry, generation and resource limits. Its signature does not replace the live entitlement query. Gemini and Antigravity are one material-author family. The team entitlement template does not compose shared Slack, Notion, n8n or other integration effects.

TeamAuthority reads signed persisted grants and authorizes every manifest path in the existing entitlement transaction. It checks live revocation, notice, scope, installed build and generation at disclosure, dispatch, immediate native execution, each local command and result admission. Review target identity is separate from the installed reviewer build. The generic work-packet schema is unchanged; no extension bag carries authority.

PrimaryProviderBudgetAuthority stores owner-signed monetary budgets for all provider lanes. Project/day and task ceilings must agree across registrations and cannot exceed signed project limits. ProviderBudgetAdmission integrates this authority into the existing primary attempt transaction for other lanes; TeamAttemptAdmission includes it with the team entitlement and nonce claim. Both use the existing workload ledger and attempt insertion. A caller's budget digest or amount is not monetary authority. Legacy stage-unit accounting remains unchanged and cannot authorize team spending. An earlier primary attempt without monetary accounting blocks new funded attempts until separately reconciled.

Reservations remain fully charged when usage is unknown or less than reserved. Only a separately authenticated, complete meter receipt records observed cost and tokens. Higher observed cost increases subsequent budget consumption; observed token-limit violations hold further project admission. The meter uses the separately trusted route-verifier secret and a distinct receipt schema. Provider prose and optional telemetry do not create a meter receipt.

The native adapter requires a protected worker with prepare and exchange operations. Before any packet/source export, the worker must produce fresh, challenge-bound signed containment evidence for unassigned source, Git history, coordinator credentials, broker keys, launcher mutation and production-network denial. It must enforce the signed runtime, native account, workspace, resource limits and local command restrictions. exchange calls the execution gate immediately before invoking AGY and the command gate immediately before each local command. The durable execution claim is single-use across processes and nonces. There is no direct local CLI, API-key, custom endpoint or unrestricted worker fallback in this adapter.

Captured native streams must have exactly one initialization and terminal completion, one native session, the bound requested model and successful exit. Review streams reject tool activity; nested provider dispatch is rejected in both modes. Signed worker changes must be within writable paths, command logs must match admitted commands, and test evidence must agree with the independent worker capture. Requested model configuration is not an observed backend-model claim. Source export reads only manifest files, checks every blob, and rejects link aliases or extra Git history.

The executable antigravity_team_worker supplies the protected Linux broker and one-attempt pinned-SSH client. Preparation discloses only public installation binding identifiers and grant/attempt digests. Full grants, filenames, packets and source bytes are sent only after authenticated qualification. Ordered signed frames prevent replay and require an immediate Director acknowledgement before native execution and each granted check. A durable create-once claim prevents ambiguous native execution from being repeated after restart. A per-native-UID file lock prevents simultaneous jobs from sharing that account.

Native AGY runs without broker keys as one unprivileged identity. Its protected permission policy denies known namespaces and a protected wildcard PreToolUse hook denies every tool category, including categories absent from that list. This hook format is documented by Antigravity's own CLI hook documentation; JSON validation alone is not evidence that installed AGY 1.1.27 enforces it. Actual wildcard denial must be proved during host qualification. The prompt carries the exact source manifest and requests a structured proposal. The supervisor applies only proposed bytes within granted writable paths and runs each exact granted command as a different unprivileged identity with a clean environment and pinned executable. Checks cannot access the native account and must not change the candidate or produce undeclared files. The runner bounds total time, output, memory, processes, open files and CPU, disables privilege acquisition and kills the process group on exit. Observed native token usage is checked at result admission; no undocumented CLI flag is claimed to enforce an exact remote token ceiling. Host acceptance must separately establish any required upstream spend or token enforcement before live use.

The host must have a separately accepted issuer-signed director-team-linux-qualification/v1 receipt binding this exact task grant, boot ID, network namespace, native/check UIDs, protected configuration and complete runtime files, native account, native project, installation and adapter bindings, expiry and actual negative access evidence, including isolation from earlier native-account task history. The receipt is consumed before readiness is returned; a general reusable host receipt cannot authorize disclosure. A subsequent task needs fresh qualification of its isolated native state, or a newly prepared isolated guest. The broker verifies protected root ownership and denies absent, expired or changed qualification. This source does not install the guest, sign that receipt or invent native authentication. Ordinary code review is not issuer adoption or worker enrollment.

The owner grant separately names native_project_id, passed through documented --project invocation and recorded as requested project. The preserved actual 1.1.27 native-attempt-001 stream emits session, cwd, requested model, tools and permission mode; it emits neither project nor account observation. Both absent observations are represented as null, never invented from the packet. The worker therefore additionally requires a protected, issuer-authenticated director-native-identity-readback/v1 artifact from native authenticated profile and project readback, bound to this grant and runtime with observed account and project IDs and an expiry. Its digest is part of the qualified protected-file inventory. This package does not implement or fabricate the issuer's native identity acquisition method; that readback and its independent acceptance remain required before use. Antigravity project invocation semantics describe the requested project flag but do not supply the absent observations.

The complete initial native-home manifest is checked only before disclosure and consumed with the task qualification. Later boundaries continue checking immutable runtime/policy and revocation; legitimate new session/cache state is captured as a bounded digest manifest and is not compared against an unchanged initial home.

TeamArtifactStore persists authenticated captures with complete returned bytes. GitTeamCandidateIntegrator reauthorizes under a locked live writer, checks the actual base tree and every source blob, and creates immutable Git blobs, tree and commit objects. It independently reads the resulting candidate bytes before recording its SHA in PostgreSQL. A private refs/director/team/ retention anchor protects its objects from Git garbage collection. It changes no checkout or branch ref and performs no merge. An interrupted database transaction can leave an orphan private anchor, which confers no candidate authority. Result artifacts use the recorded candidate SHA, not a provider-supplied SHA. Startup verifies team columns, keys, checks, immutable triggers and the execution uniqueness index; accepted restart verifies before migration can repair a changed guard.

Daily monetary admission for ordinary primary providers

Every live primary attempt now requires a PrimaryProviderBudgetRouting dependency, including when LANGGRAPH_PRIMARY_ANTIGRAVITY_TEAM_ENABLED is false. Offline simulation keeps its existing provider doubles and does not create monetary authority. Team assignments retain their separate worker and entitlement checks and reserve money exactly once through the same primary ledger.

Automatic live construction reads the existing ENTITLEMENT_CONTROL_PLANE_ENABLED, ENTITLEMENT_POSTGRES_DSN_FILE, ENTITLEMENT_POSTGRES_SCHEMA, ENTITLEMENT_TRUSTED_VERIFIER_SECRET_FILE, ENTITLEMENT_ROUTE_VERIFIER_SECRET_FILE, ENTITLEMENT_OWNER_AUTHORITY_SECRET_FILE and ENTITLEMENT_ALLOW_INSECURE_LOCAL_POSTGRES configuration. The configured entitlement schema must already be provisioned in the same database and role as the primary store. Startup validates its existing manifest and guards in a read-only transaction. It does not initialize a schema, register a project, generate keys, or issue a signed budget.

Before a task's paid attempts can run, its existing owner-signed primary-provider-budget/v1 documents must be registered using PrimaryProviderBudgetAuthority.register for the exact task, project, provider and UTC day. Registration still requires an active signed project registration. No runtime auto-signer or automatic per-task enrollment is supplied here. Missing or non-unique daily authority stops the selected lane before dispatch.

The signed reservation must cover the actual per-attempt USD ceiling passed to the adapter, rounded up to whole micro-USD. The effective task and daily ceilings are the lower of the signed document and MAX_TASK_BUDGET_USD / MAX_DAILY_PROVIDER_BUDGET_USD; configuration alone cannot grant spend. All providers share the project's daily sum in the canonical primary schema. Signature, task/provider/project binding and the signed UTC day are verified inside atomic attempt admission. A v1 daily budget expires at the next UTC midnight. Concurrent attempts cannot each spend the same remaining allowance. The spend row, workload admission and STARTED attempt commit together.

Failed, interrupted and ambiguous attempts retain their complete reservation; authenticated usage can increase the accounted amount but cannot refund it. An earlier primary attempt without monetary accounting still requires explicit reconciliation. A simulation history must not be relabeled as funded live history or erased by choosing a new schema to evade accounting.

This is durable monetary admission, not proof of a vendor-enforced billing cap. Some API/native transports do not enforce the supplied USD context or an exact token ceiling upstream. A timeout or output byte bound is not a hard USD limit. Those routes require independently established upstream spending bounds before their reservations can be treated as a guaranteed maximum bill. This change makes no paid call and does not establish that transport evidence.

For the primary OpenAI Responses route, the exact signed budget's token_limit now travels from atomic admission to the adapter as a total-token allowance. It is never read from model-authored packet fields or converted from USD. The adapter first calls the authenticated Responses input_tokens endpoint with the identical configured model, instructions, input, reasoning and tools. It permits at most one generation with max_output_tokens equal to the remaining allowance; that output cap includes reasoning tokens. An invalid count or no remaining allowance stops before generation. Both requests share one cancellable deadline; the count response is bounded to 4 KiB and generation response to 1 MiB, including when a server keeps sending small chunks. Neither request is retried. A non-completed result, malformed output, missing usage, changed input count or exceeded total is not recorded as success.

The returned token usage is provider telemetry, not a signed ProviderUsageReceipt or a new monetary authority. This check bounds the generation request under the provider's counting/output contracts; it cannot undo a provider-reported violation after execution. It does not establish count-endpoint pricing, a hard USD billing cap, or equivalent enforcement on other transports. Cancelling local I/O cannot prove that the provider stopped remote computation; an interrupted generation remains ambiguous. Runtime enrollment and paid activation remain separate.

The request shape follows the Responses input-count contract. The shared deadline uses asyncio.timeout because HTTPX timeouts cover individual I/O operations.

PrimaryTeamRouting composes enrolled runtime-proof, worker, artifact and repository services. DefaultPrimaryActivation accepts that explicit typed composition. When team mode is enabled, automatic startup without it fails closed. The primary roster can plan Antigravity engineering and independent review; selection alone grants no permission. Each exact planned assignment must have its own owner-signed registered grant, and every selected provider uses the shared authoritative monetary admission. Old subordinate transports remain closed and cannot execute a team assignment. Host enrollment, issuer acceptance, activation generations and live cutover remain separately gated.

Use team_packet_adapter(settings, ...) only for an explicitly selected team assignment with its grant and authoritative attempt. The existing subordinate adapter remains the default. Register the team attempt using format identity antigravity-team-engineering-v1 (the parallel ledger's identifier form) and team_admission=TeamAttemptAdmission(...); the signed envelope retains the versioned contract name with /v1.
