Entitlement control plane (default off)

Status: Mechanism only. Default off. No readiness router, provider dispatch, or external-effect consumer wires the dormant action-boundary query.

SQLite rights provisioning, startup authorization snapshots, and the pending readiness hunk are removed. Entitlements live in PostgreSQL with immutable generation/event lineage, generation CAS, idempotent stored outcomes, and mandatory owner notices.

Contracts and signing

Contract Purpose
SignedEntitlementTemplate/v1 Owner-signed profile template composed with universal shared-integrations/v1
ProjectRegistration/v1 Owner-signed project/profile registration with destinations, scopes, budgets
InstallAttestation/v1 Authenticated install evidence with non-self-referential verifier signature
EntitlementEvent/v1 Immutable GRANT, SUSPEND, REVOKE, RESTORE, SUPERSEDE, UNINSTALL
OwnerNotice/v1 PENDING, DELIVERED, FAILED, ACKNOWLEDGED

Signing bytes exclude signature fields. Subjects never declare rights.

Dormant action-boundary query

EntitlementControlPlaneStore.query_action_boundary() intersects live entitlement with registration generation, template composition, build digest, repository/ref/path, budget, notice deadline (five-minute fail-closed without scheduler), and audit lineage.

Runtime authorization proofs are single-use effect claims. The first exact, fresh, signed proof can reserve its installation/action/destination/effect/build/source binding. An exact replay receives the stored binding but is denied permission to execute the effect again; reuse of the nonce with any different binding fails closed.
