Capability note for work order WO-FRM-20261023-CAP01 (issue #299, capability verification). Written 23 October 2026 by the Claude route as the sole accountable author.

What the route actually is

The Director starts a Claude agent session (Claude Agent SDK / Claude Code) inside one dedicated git worktree and branch. In this route the agent has no native shell, no browser, no other provider and no permission editing. Its only effects go through the director_git MCP tools, which are scoped to the worktree root:

Tools available on this route
ToolEffectLimit
worker_git_statusReports the head, base, branch, changed files and bound PRRead-only
worker_git_read_fileReturns the file content and its SHA-256, or ABSENTRead-only
worker_git_write_fileWrites one fileCompare-and-swap on expected_sha256; must be an allowed path
worker_git_commitCommits the listed pathsNormal git hooks run; no bypass
worker_git_publish_draftPushes the branch and opens a draft PR against mainDraft only; no merge or review authority
worker_git_commentComments on the PR bound to this branchBound PR only

How the Director gives a scoped task

The Director sends one JSON object. The agent treats allowed_paths as a hard boundary and the numbered steps as the whole job:

{
  "task": "[Director-Orchestrator] [ISSUE-NNN] [WO-...] numbered, bounded steps",
  "allowed_paths": ["path/to/the/only/file.ext"]
}

A good task names the exact path, the expected starting state (an existing SHA-256 or ABSENT), the commit message intent, the PR title and the checkpoint time for the readback. Anything outside that scope gets refused and reported. The agent does not quietly widen the scope.

Draft-only GitHub publication and hooks

  • Writes fail closed if the file changed since it was read, because the hash no longer matches. The agent re-reads the file before deciding anything.
  • Commits run the repository's normal hooks. A hook failure is a real result to report, not something to route around.
  • Publication opens a draft PR to main and nothing more: no ready-for-review flip, no merge, no CI rerun and no deployment.

Errors and UNKNOWN: stop and reconcile

If a tool returns an error, a refusal or an ambiguous effect (for example, a timeout where the commit or push may have happened), the agent stops. It does not retry blindly or try a workaround. It reads the state back with worker_git_status or worker_git_read_file, reports exactly what it observed, and repeats a successful effect only when the readback shows the effect is missing. A refusal is final for that work order. Any fact the tools did not return is written as UNKNOWN.

  3. A merge by that reviewer or another authorized merger, never by this route.
