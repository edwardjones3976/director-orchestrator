Z.ai route capability note

Director-Orchestrator · ISSUE-299 · work order WO-FRM-20261023-CAP01 (CAPABILITY_VERIFICATION) · 2026-10-23

1. Purpose and scope

This note records what one bounded qualification actually exercised on the zai route: a scoped JSON work order, delivered natively, driving only the director_git MCP toolset. It describes observed mechanics and stated policy. It is not a review, an approval, or a claim about any completion stage beyond evidence actually returned by a tool call.

2. The actual route

The Director hands the route a single scoped JSON task. The task names the work order, an allowed-paths list, a start timestamp, and an ordered list of bounded steps. Everything else is out of scope by construction.

  • Scoped JSON task: one {"task": …, "allowed_paths": […]} object; every file write must fall inside the allowed paths (here, exactly docs/provider-capabilities/zai-20261023.html).
  • Tool surface: six director_git tools — status, read_file, write_file (with an expected-hash precondition), commit, publish_draft, comment. No native shell, no other provider call, no browser, no permission-file edit, no fallback route.
  • Draft-only publication: worker_git_publish_draft opens a draft pull request against main. A draft cannot merge; converting or merging it is not a capability this route holds.

3. Normal hooks

worker_git_commit runs the repository's normal hooks. The route holds no bypass flag and may not add one. A hook failure surfaces as a returned error, which is treated as a stop-and-report condition, not something to evade.

4. Error and UNKNOWN behavior: stop and reconcile

  • Refusal is final. If a tool or gate refuses an action, the refusal is reported; no workaround, renamed retry, or side channel is attempted.
  • Unknown is written as UNKNOWN. Anything not exposed natively — for example a session identifier — is recorded as UNKNOWN rather than inferred from a launcher executable or harness label.
  • Ambiguous effect stops the run. If a call's effect cannot be read from its returned payload, the step is not repeated and the discrepancy is reconciled before any further effectful call.
  • No claim ahead of evidence. No completion stage is asserted before its returned receipt exists: the file write cites the read-back state, the commit cites the returned commit SHA, the publication cites the returned PR URL.

5. Independent gates this route does not hold

  1. Independent review — a non-author provider reviews the draft; the author cannot review or approve its own contribution.
  2. CI — checks must come from a real executed run at the PR head; a green badge or a stub run is not accepted in place of that.
  3. Merge — held by the reviewer/Foreman protocol, never by the author, and never defaulted to the owner as a request.
