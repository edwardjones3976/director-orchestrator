Grok scoped coding route

This offline note records how the grok provider route works as a bounded Director-Orchestrator worker. It is an implementation qualification file only. Later commit SHA, draft PR URL, and ACK comment URL cannot live here because this file is written before those tools return.

Actual route

The accountable native author for this assignment is the xAI Grok Build worker on the grok route. Director hands a single scoped JSON work order with an explicit allowed_paths list and a start time. For this qualification the worker may use only the director_git MCP tools: status, read, write, commit, draft publish, and bound PR comment. Native shell, other MCP servers, other providers, browsers, permission-file edits, self-review, merge, and deployment are out of scope. A tool refusal is final: the worker reports it and stops.

Scoped JSON task from Director

Director or Foreman issues one work order object. The worker treats that object as the whole assignment. Typical fields are the task narrative, allowed_paths, start timestamp, and hard stops (no workaround, no extra project, no source ACCEPT). The worker first calls worker_git_status and reads the named file, then writes only inside the allowed path. Expected file hash is the live SHA256 from the read, or the token ABSENT when the file does not yet exist. Effects are claimed only after the matching tool returns them.

Draft-only GitHub publication

Publication for this route is worker_git_publish_draft against main. The result is a draft pull request. The worker does not open a merge request, retarget another branch, approve, or merge. Independent review, CI, and merge remain later gates owned by other roles. This worker cannot review or accept its own implementation.

Normal hooks

Commits go through worker_git_commit with the exact allowed path list and an accurate docs message. Repository hooks run normally. Hook bypass is not authorized on this route. If a hook fails, the worker stops and reports the returned error instead of retrying through another interpreter.

Error and UNKNOWN stop-and-reconcile

On refusal, ambiguous effect, missing receipt, or an UNKNOWN that would change the next step, the worker stops and reconciles with Director. It does not invent a second path, claim a completion stage without the tool receipt, or fill identity fields by guessing from a launcher executable. Model and session stay UNKNOWN unless the native client actually exposes them. Shared-host facts that are not required for the route note stay out of the file.

Independent review, CI, and merge

Writing, committing, drafting a PR, and posting an ACK comment are worker actions. They are not source review, owner approval, CI green, or merge. A later independent reviewer and the existing CI/merge process decide those stages. The ACK on the bound PR is receipt of the assignment only.

Authorship, sender, and communication

Provider authorship is the grok/xAI Grok Build worker. GitHub writes on this host are sent by the shared account edwardjones3976. Those are different facts: the worker owns the text; the shared account is the transport sender. GitHub comments returned by worker_git_comment are the verified communication channel for this qualification. Native Slack is not verified on this route and is not used as proof of delivery.

Commit, tree, draft PR, and comment URLs belong in the PR ACK after those tools return. This file does not claim those stages. Native session identity is UNKNOWN in this client unless separately recorded by Foreman metadata.
