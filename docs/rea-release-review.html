Release inspection · Opt-in static lab

REA release reviewer (opt-in)

Opt-in CLI and Linux Docker qualification lab for comparing Electron ASAR release payloads with diffoscope and optional Reverse Engineer Anything (REA) static evidence.

Opt-in CLI and shared entry point

The project entry point scripts/rea-release-review.py delegates directly to scripts/rea_release_lab/review.py (main(argv=None) -> review(...)). It accepts the five positional paths, the optional --rea switch, and repeatable --source-path selection:

python scripts/rea-release-review.py <left> <right> <left_tree> <right_tree> <output> [--rea] [--source-path PATH ...]

Selected-source example (forwarding exact inventoried relative paths to both REA analyses while keeping the default 120-second per-subprocess bound unchanged):

python scripts/rea-release-review.py left.asar right.asar left_tree right_tree out_dir --rea --source-path .webpack/main/index.js --source-path .webpack/renderer/main_window/preload.js

Before creating output or launching external tools, review(...) validates that left and right are regular files, left_tree and right_tree are directories without root or member symbolic links (or native junctions where supported), output does not already exist, and output is not inside either input tree. Any --source-path values require --rea and must be safe relative POSIX paths (rejecting empty, absolute, Windows-drive, backslash, or traversal segments before side effects). Flagless behavior and the default timeout=120 subprocess bound remain unchanged. It writes review.json (schema rea-release-review/v1), index.html, and per-subprocess receipts (*.receipt.json, *.json, *.stderr).

Complete inventory, partial relationship scope, and native limits

File-change coverage and semantic relationship coverage are tracked separately in review.json (analysis_scope):

  • Complete artifact & inventory identity: left_sha256, right_sha256, and each side's normalized_result.root_artifact_sha256 always bind to the complete ASAR bytes (never a subset hash). With --rea, inventory(...) compares all files across left_tree and right_tree. Without --rea, diffoscope_paths(...) translates native diffoscope unified diffs and directory file list additions/removals into regular-file leaves inside the verified roots, without counting parent directories as changed files and while refusing escaping, absolute, or link/junction paths.
  • Partial semantic relationship scope: Passing repeatable --source-path forwards those exact paths to both rea analyze-javascript-application calls. Semantic relationships outside selected files remain UNKNOWN, and analysis_scope.semantic_relationship_coverage reports partial (or unknown if optional coverage metadata is absent; never relabeled complete). Native full-graph payloads stay in left-analysis.json and right-analysis.json rather than being duplicated in review.json, while review.json records requested_source_paths, per-side source_selection, graph_coverage, statistics, limits, and evidence links.
  • Unchanged control & 120s bound: On an unchanged control (same_artifact: true), REA subprocesses are skipped and analysis_scope.mode is skipped_identical_artifact. Unscoped large releases (for example, large Electron/Webpack ASARs) can hit the default 120-second per-subprocess timeout and have not completed unscoped analysis.

Verified extraction and ASAR companions

The caller supplies independently verified extracted trees (left_tree and right_tree); review(...) does not authenticate arbitrary trees against ASAR contents and executes no vendor application code. Companion ASAR files (left and right) are SHA-256 hashed in review.json. When --rea is passed and left differs from right, REA analyzes each companion archive statically via rea analyze-javascript-application and rea compare-application-versions, and review(...) verifies that each returned normalized_result.root_artifact_sha256 matches the input artifact digest.

Full lab qualification runs on a Linux Docker host via scripts/rea_release_lab/run_all.py with isolated containers (--network none, --memory 2g, --cpus 2, --rm, and owned doa.rea-lab.run / doa.rea-lab.step labels). The container definition in scripts/rea_release_lab/Dockerfile pins:

Owned-fixture benchmark and unchanged control

scripts/rea_release_lab/benchmark.py builds owned Electron ASAR fixtures (baseline, candidate, and an identical control copy of baseline) and compares diffoscope against diffoscope+rea across repetitions. On an unchanged control, same_artifact is true, changed_paths is empty, and --rea skips REA subprocesses.

AgentEnv export, startup, final-state, and fidelity checks

Qualification separates AgentEnv checks into distinct stages rather than treating a single pass as end-to-end proof:

  • Export (agentenv-export): rea environment-build exports an AgentEnv bundle from recorded HTTP traffic (training.har).
  • Fidelity (agentenv-fidelity): rea inspect-web-network-capture and rea environment-compare verify held-out recording agreement (summary.agreement == 1) against probe.har.
  • Startup (framework-smoke): agent-env run <bundle> --task smoke checks container/server startup after prepare_agentenv.py.
  • Final state (framework-workflow): scripts/rea_release_lab/agentenv_verify.py exercises a scripted folder create/rename/read/delete workflow and verifies both the restored final state and a negative-control assertion.

Rapid timestamp guarantee and limitations

The digest-bound patch in scripts/rea_release_lab/apply_rea_precision.py replaces millisecond-truncated interval comparisons with exact OffsetDateTimeInstant coordinates (StateRecordChronology) and timing.end checks. scripts/rea_release_lab/rapid_checks.py verifies unpaced same-millisecond HTTP captures (injected_pause_seconds: 0) as well as synthetic disjoint, overlap, missing-duration, and unusable-duration cases; scripts/rea_release_lab/mcp_stdio_check.py verifies the same interval-withholding and unusable-duration limitations over stdio MCP.

Limitations: unconfirmed writes with missing or unusable completion durations remain withheld rather than guessed, and ordinary host Python unit tests in tests/test_rea_release_review.py use mocked external tools and an isolated subprocess for lab discovery without running Docker, live providers, or network calls.

Known versus unpriced costs and unchanged release gates

Each static review records model_calls: 0, incremental_model_cost_usd: 0, and infrastructure_cost_usd: null. The benchmark summary records incremental_model_calls: 0, incremental_model_cost_usd: 0, infrastructure_cost_usd: null, and codex_authoring_cost_usd: null, noting that tool timings exclude installation, shared extraction, and authoring. Zero per-review model calls does not make authoring, Docker/CI compute, or qualification free; unpriced infrastructure and authoring costs remain UNKNOWN unless separately measured.

Epistemic and governance boundaries:

  • Static relationships do not establish runtime behavior, universal runtime correctness is not claimed, and file-change coverage does not establish semantic or runtime accuracy.
  • Unscoped large releases are not claimed completed, and no new Cloud qualification is claimed.
  • This opt-in command grants no automatic model execution, deployment, installation, or approval; existing release controller, site coordination, CI, and Warden gates remain unchanged.
  • Existing local native Node/AgentEnv source is unchanged and remains reusable by per-file hashes; affected reviewer, CLI, fixture, and real comparison checks require fresh execution results and independent review.
