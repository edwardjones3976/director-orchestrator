Neutral primary authenticated claims

WO-20261116-004 revision1 implements a durable store prerequisite only. Primary neutral ingress remains held. This source change does not enable admission, graph execution, standing grants, native delivery, or any live route.

Store contract

claim_authenticated_primary_intake retains the existing keyword arguments and (task_id, created) result. Omitted authentication class means slack_gateway_attested; Slack digests and exact-nonce replay behavior remain unchanged. A fresh Slack nonce for the same source still conflicts.

A verified neutral caller supplies authentication_class=neutral_gateway_attested, original source_provider and source_event_id, verified nonce_digest, full signed intake payload_digest, and a proposed task ID. The store trusts the upstream verifier; it does not verify signatures or map actors to owners. Bearer and unknown authentication classes are refused.

Neutral event identity is document_digest of the object with domain=director-primary-neutral-source/v2, provider and source_event_id. Neutral nonce identity uses a separate object with domain=director-primary-neutral-nonce/v2, provider and nonce_digest. The event key excludes actor, conversation, body and deadline so changes to those signed fields conflict on the same event. An optional supplied idempotency digest must equal the derived event key. Payload is the digest of the complete signed intake, including original actor and timestamps, excluding proof metadata such as a fresh nonce or proof issuance time. No digest is rewritten into Slack fields.

Exact neutral replay returns the original task with created=false. An identical event with a fresh nonce appends an alias to the original nonce, preserving payload and authentication class. Reusing any canonical or alias nonce for another event or payload conflicts. Different providers have separate event and nonce domains. Reusing a task ID for a different source conflicts. Claims can exist without graph projections; replay never confers permission to repeat a grant, reservation or dispatch. The coordinator only forwards these fields after its existing active-generation check.

Installed schema upgrade

The existing versioned control-plane setup runs the claim v2 constraint migration inside its DDL transaction and schema advisory lock, following the existing guarded constraint migration convention. It does not rely on CREATE TABLE IF NOT EXISTS. The new nullable original_nonce_digest column marks this additive claim schema. Existing v1 rows retain all original values and timestamps, with a null alias reference. Source/task unique constraints become canonical-only unique indexes; a composite foreign key binds each alias to the same nonce/source/body/task/class tuple. Aliases are permitted only for the neutral authentication class. The existing append-only update/delete guard remains installed.

All DDL and indexes commit together. Failure after the constraint migration rolls back its column, constraints and indexes as well as other setup changes. Repeated setup recognizes the installed column and leaves the claim history unchanged. Claim operations take transaction-scoped source, nonce and proposed task advisory locks in sorted numeric key order before reading either identity. Concurrent fresh nonces for one event select one canonical task; conflicts do not append history.

Receiver fact and replay timing

The existing canonical claim created_at is the database-owned first authenticated store receipt time. It is already correlated with the original source digest, task ID, nonce digest and signed payload digest; no historical timestamp is backfilled. read_authenticated_primary_intake(task_id) returns that canonical fact as receiver_received_at, even without a graph projection. The value is timezone-aware and represents the PostgreSQL transaction start at the authenticated store boundary. It does not measure time spent in the gateway before that boundary. Sender received_at remains a distinct signed body field.

The canonical time survives commit followed by response loss, process restart and replay. Fresh-nonce aliases have their own database created_at for replay receipt; the original timestamp is read only from the canonical row. Exact replay does not add a second receipt or alter the original. These facts do not backfill historical trials or establish ranked timing credit.

Verification and remaining gates

Focused real-Postgres coverage is in tests/test_primary_neutral_claims_postgres.py, with existing Slack coverage in tests/test_primary_authenticated_ingress_postgres.py. Tests exercise clean setup, an exact installed v1 table and rows, idempotent restarts, injected upgrade failure rollback, both classes, domain separation, payload conflicts, nonce aliases, concurrent races, and orphan-claim receipt stability. They do not invoke native dispatch, grants or reservations.

Local Postgres execution is NOT_RUN: test DSN is unset and the documented local PowerShell lane is frozen. No replacement database is authorized. Real database tests must run in approved CI on the exact pushed follow-on head, followed by independent Claude source/test review and the remaining release gates. Source implementation, local checks and test collection are not acceptance or M2 completion.
