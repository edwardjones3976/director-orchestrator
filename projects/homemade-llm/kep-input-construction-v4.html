Construction-only KEP inputs, rule v4

Authority and scope

WO-C1 froze the A2 constraints selector; WO-C2 authorizes this implementation and an offline supply count over the full pinned Kubernetes enhancements archive. The earlier 204-group population is a regression fixture, not the new selection universe. Its expected pre-token funnel is 204 → 83 lexical → 75 whole/source-bound → 73 allocation-valid. Neither that expectation nor an offline count establishes training admission.

The four target fields and shared input contract remain unchanged. The constructor emits target-free kep-input/v1 records with disposition construction_only. It performs no model, provider, GPU, network, grading, training, or held-out access. Trust root v2r9 and its two-lead approval remain external prerequisites; this implementation does not edit or approve any root.

The source of selector behaviour is v4a2_funnel.py, SHA-256 538b22adb847484b331d9e7073c0dd9b8691fd43efe6d1f1d166f54cc2a7d718, ported into kep_constraints_v4.py. The port removes the analysis script's filesystem and reporting entry point, adds source-span results for construction, and identifies refusal roles. Its lexical expressions, scoped units, tier precedence and allocation behaviour are retained.

Frozen selection contract

Rule v4 removes the whole-section Risks and Mitigations → Notes/Constraints/Caveats alias. Graduation Criteria → Alpha Graduation Criteria remains available under the existing canonical-before-alias, duplicate-refuses rules. Source headings are never renamed.

StageContract
Tier 1Search genuine Notes/Constraints/Caveats units. Any lexical candidate reserves this tier, even if every candidate subsequently fails whole-unit or length checks.
Tier 2Only when tier 1 has no lexical candidate, search units in Risks and Mitigations and the leads of uniquely named Proposal and Design Details headings, ordered by source position. A Proposal/Design Details lead ends at the first following heading, including a subheading.
LexicalThe item matches the frozen REQ expression. Neither item nor attached scope matches RISK or PROSPECTIVE. An item ending in a question mark is excluded. This is a lexical selection rule, not a claim of semantic truth.
Whole/source-boundRetain the whole paragraph or list item with its complete subtree within A2's content blocks, plus each ancestor item's own lines and any governing lead-in. Emit original Unicode source slices. Refuse comment-tainted units, overlapping scope, and units outside the inclusive 30–600 character limit; never trim them to fit.
Excluded contentExact template lines, comments, fenced code, table rows beginning with a pipe, checkbox lines, headings and blank lines delimit A2 content blocks. A preceding block ending in a colon can supply governing scope. Scope never crosses a subheading. Future, hypothetical and advisory markers are rejected for every subject.
AllocationReserve the objective and all four mandatory role minima first in a shared 2,100-character pool. Fill support roles in their existing order. Summary and Motivation each retain an independent 200-character allowance with no transfer; total maximum is 2,500 characters. Count exact emitted Unicode code points, including retained line endings. Missing genuine mandatory source, overlap, or accounting mismatch refuses the group.

A constraints unit is atomic. Its source heading is emitted once before that heading's first selected unit. Already emitted enclosing spans are not repeated; partially overlapping units are skipped whole. A nonfitting next allocation unit stops that role, with no clipping or skip-ahead for fit. The other roles use the unchanged v3 paragraph allocator. The original source order determines the final context span order.

The exact case-insensitive REQ, RISK and PROSPECTIVE expressions are maintained in the selector module. They include prerequisites, negation and numeric bounds such as “at most”, “at least”, “limited to” and “up to” followed by a digit. Changing an expression changes this frozen rule and requires a new decision.

Token filtering remains in the existing separate offline renderer step: rendered input prompt at most 1,400 tokens; over-limit prompts are refused, never retrimmed. The counter reports tokens: NOT_MEASURED. V4 does not carry the superseded v3 minimum of 200 usable inputs. It grants no replacement training threshold or acceptance verdict.

Compatibility and publication

prepare_kep_inputs.py retains v2 and v3. Omitting --rule keeps policy-driven selection. Explicit --rule v3 requires a v3 policy and preserves v3 construction bytes for the same pinned evidence and clock. The regression suite pins a synthetic complete v3 inputs.jsonl SHA-256 to 989de65b9c97a80e0942024057fce98bf9ce6dec12fdea8d6d453eab3826a3e5 and compares implicit and explicit v3 output.

Publication with --rule v4 requires the existing archive, tree, census, license, policy, policy hash and new output directory arguments. The policy must exactly equal v4_policy(frozen_at) in the constructor, including the A2 source pin, template pin, allocation and token contract. The actual policy file's SHA-256 and an authentic pre-construction freeze timestamp are still required. The helper describes the contract; calling it is not approval. An explicit rule/policy mismatch refuses before source construction.

Archive, tree, license, census and per-source Git blob checks, metadata identity/status qualification, bounded reads, secret-marker screening, source-span validation, chronology and no-clobber Windows publication remain in force. Inputs retain the original namespace round-robin selection rank. SHA-256 ranks reported by the counter are separate ranks and do not change historical construction ordering. See the existing construction and publication contract for shared guarantees.

Offline full-archive count

On the authorized Windows host with Python 3.14 and existing test dependencies, run from the assigned worktree:

$kepArchive = 'C:\llm\reports\codex-m2-delegation-20260930\kep-route-prestage-20261002'
python -B projects/homemade-llm/eval/prepare_kep_inputs.py --rule v4 --count-only `
  --archive "$kepArchive\enhancements-pinned.tar.gz" `
  --tree "$kepArchive\tree.json" `
  --census "$kepArchive\metadata-census.json" `
  --license "$kepArchive\LICENSE"

Planning estimate: 1–5 minutes on a local CPU and SSD; this is not a measured runtime. The command traverses the full pinned census, authenticates every metadata entry, and analyses every eligible positive unique group. It does not read inputs-204.jsonl or limit selection to the old extraction's successful groups. Archive commit: f7be055669b365e9b4ab3905bda6ef385e0c84ca; archive SHA-256: da037ba8c8e68aa7033d256beff5da7cf3605b83678d46b0f6c403947c574618.

--count-only accepts only v4 and rejects policy, policy hash, output directory and dry-run arguments. It uses an in-memory rule snapshot, creates no output artifact and disables import bytecode writes when invoked from the CLI. It does not fabricate a frozen publication policy or bypass evidence pins. Zero kept groups is a successful count, not successful construction.

Stdout is one JSON object with protocol kep-input-counts/v4. stage_counts reports metadata candidates, eligible groups, analysed groups, lexical, whole/source-bound, allocation-valid, usable inputs and token status. allocation_valid is the A2 pre-token B stage; usable_inputs additionally excludes any source rejected by subsequent secret-marker screening. Each kept_groups entry contains group_id, the SHA-256 of its UTF-8 group ID, and its zero-based rank after sorting by that hash then group ID.

Every refused census group is printed separately to stderr as one JSON line with group_id, role and a fixed reason. Source parsing uses role source, eligibility uses metadata, missing evidence names the affected role, and shared budget/overlap failures use allocation. A rejected run may also print a batch-level refusal object. No source excerpts are printed. Normal v4 publication and dry-run use the same per-group refusal stream and retain decisions in the manifest.
