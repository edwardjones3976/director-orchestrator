One-page run sheet: adapter v0.1 on a rented GPU

The single sheet the host seat follows for the first training session, once the full training batch is frozen. The pilot of orders D-02 and D-03 is only the go or no-go gate for scaling; the batch this sheet trains on comes from the separate scale order that follows a pilot GO. It replaces acceptance rounds with a fixed sequence of checks, a run, an export and a teardown. Every number here is a pin or a gate already recorded; nothing here is a run result. Where a value must come from the frozen batch or from the installed root, the sheet names the source instead of guessing it.

Before the GPU (on the host, no rental yet)

  1. Headroom. Read the spend ledger; proceed only with at least USD 10 unreserved headroom under the owner-reported remainder. Record the figure.
  2. Batch. Confirm the frozen training batch manifest hash, row count by split, group count by split, and that every row hash matches accepted.jsonl.
  3. Dev limit. Measure the longest dev prompt through the admitted renderer; set --epoch-context-limit to that count plus 2,048. Write both numbers down. Then validate the staged publication in epoch mode inside the pinned image, so the authenticated loader runs and not the legacy one: train_adapter.py --check-only --rows <publication>/rows/accepted.jsonl --base unsloth/Qwen3-8B-unsloth-bnb-4bit --revision 62efd7f9d748e394734a7adae2adf96e13a2abc8 --epochs <n> --epoch-context-limit <measured> --publication-binding <binding> --report <report.json>. Without --epochs, --check-only uses the legacy row loader, which refuses the admitted publication's report.
  4. Digests. Read the student snapshot and the expected-digest list with the two-consecutive-read rule the loader already enforces; keep the receipts. Any mismatch stops here.
  5. Package. One archive containing the complete staged epoch publication the trainer authenticates before loading any model, laid out as it expects: rows/accepted.jsonl, rows/report.json, rows/profile.json, train/train_adapter.py, train/prompt_template.py, eval/predict_dev.py and eval/dev_selection.py (the PUBLICATION_PAYLOAD_FILES set), with train/epoch_authority.py; the authority files for the read-only mount /run/route-r-authority (root-pin.py, root.json, publication.json, as epoch_authority.production_paths reads them on Linux); the pinned image reference; the student and merge-base digest lists; the manifest v4 root; and this sheet. Prefer the accepted C57 to C61 Linux bundle and launcher (bundle commit b42c1c6f, manifest 06bd1686, rebuilt for the frozen training batch) over a hand-assembled archive. Before renting, validate the archive offline: unpack it into a scratch Linux directory or WSL, mount the authority files read-only at the same path, and run the same epoch-mode --check-only command from the dev-limit step against it; any refusal stops here. The model weights are not packed from the host (its read path has corrupted bytes before); they are provisioned on the instance in session step 3. Hash the archive; record it.

The session (one rented GPU, one operator, no other writer)

  1. Rent one instance (A10 24 GB proven; H100 if available), named for this order; arm automatic termination at the 4-hour mark before anything else runs. Record instance id, region, start time and the termination readback.
  2. Transfer the package over the authenticated route that worked in C61 (SSH over port 443). Verify the archive hash on the instance. Pull the pinned image by digest only; never by tag.
  3. Snapshots. With the network still on, download both pinned snapshots at their exact revisions into the trainer's Hugging Face cache directory on the instance (for example huggingface-cli download <repo> --revision <sha> --cache-dir <HF_ROOT>/hub); verify every file against its expected-digest list with two consecutive matching reads; any mismatch stops the session. Only then does the container run offline.
  4. Load check. Start the container offline (--network none after the pull and the snapshot provisioning), with the snapshots and batch mounted read-only. Confirm the loader's verified-read receipts and the tokenizer and pad-row allowances already merged (#497, #498, #509). Any refusal stops the session; no tolerance is added on the instance.
  5. Train. One epoch-mode run: train_adapter.py --rows accepted.jsonl --base unsloth/Qwen3-8B-unsloth-bnb-4bit --revision 62efd7f9d748e394734a7adae2adf96e13a2abc8 --epochs <1 to 6> --epoch-context-limit <measured> --expected-digests <list> --trusted-digest-root <root> --publication-binding <binding> --report <report.json>. Epoch mode refuses to start without the explicit --base and full 40-character --revision of an allowed pin; environment variables do not satisfy that check. The trainer's own gates apply unchanged: response-only loss, gradient accumulation 8, learning rate 1e-4, the evaluation at the epoch-1 midpoint and every epoch end, the stop rules of D-M2-39 (stop if the primary metric or any field falls more than 5 points below its best, after two non-improving epoch ends, or at six epochs), checkpoint selection by the exact-item F1 of D-M2-38. The trainer has no wall-clock stop, so wrap the container in an outer bound on the instance: timeout --signal=INT --kill-after=300 9000 docker run .... If the bound fires, the run is FAILED: the trainer catches the interruption, marks its callback failed and writes a report with no selected adapter, which the export refuses. Do not export. Retrieve the report, the saved checkpoints, the hashes and the container log as failure evidence, tear down, and report; any resumed or recovery run is a new Director order. Size the epoch count so the measured rate fits well inside the deadline, so the bound is a safety net rather than the normal stop.
  6. Export. Merge the selected checkpoint onto the bf16 pairing and export the Q4_K_M GGUF with the image's prebuilt llama.cpp, exactly as export-adapter.ps1 does on the host; hash the adapter leaves and the GGUF twice.
  7. Retrieve. Copy report, adapter, GGUF, hashes and the container log back over the same route; verify every hash after the copy.
  8. Teardown. Terminate the instance; confirm with an authenticated instance list showing none; record the usage figure the provider shows.

After the GPU (on the host)

  1. Import the GGUF into LM Studio under a new model name; serve one constrained completion with serve-smoke.ps1 -SingleHost style checks bound to the report; record the response hash.
  2. Score Set A with the unchanged pipeline (build_inputs.py, generate_candidates.py, score_packets.py, two non-author graders: the Claude and Grok pair); record field-level acceptance against the base model's M1 score as the regression baseline.
  3. Run the IFEval and GSM8K regression at the pinned harness revision from the regression freeze (D-M2-30); at most a 3-point drop per task.
  4. Record everything as one decision-log row: pins, batch hashes, epochs run, selected checkpoint, dev metric, Set A result, regression result, rental cost. Then the Director rules on v0.2 or on the teacher change.

Stops

Any of these ends the session and is reported, never worked around: a hash mismatch at any step; a loader refusal; headroom below the stated figure; a missing termination readback; a provider or route failure that would need a second rental in the same session (a second rental is a new order); any instruction to add a tolerance, change a pin, or touch held-out text.
