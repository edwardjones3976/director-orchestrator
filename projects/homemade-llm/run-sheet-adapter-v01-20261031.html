One-page run sheet: adapter v0.1 on a rented GPU

The single sheet the host seat follows for the first training session, once the pilot batch is frozen (orders D-02 and D-03). It replaces acceptance rounds with a fixed sequence of checks, a run, an export and a teardown. Every number here is a pin or a gate already recorded; nothing here is a run result. Where a value must come from the frozen batch or from the installed root, the sheet names the source instead of guessing it.

Before the GPU (on the host, no rental yet)

  1. Headroom. Read the spend ledger; proceed only with at least USD 10 unreserved headroom under the owner-reported remainder. Record the figure.
  2. Batch. Confirm the frozen pilot batch manifest hash, row count by split, group count by split, and that every row hash matches accepted.jsonl. Run train_adapter.py --check-only --rows <accepted.jsonl> --report <report> inside the pinned image; it validates rows and exits without a GPU.
  3. Dev limit. Measure the longest dev prompt through the admitted renderer; set --epoch-context-limit to that count plus 2,048. Write both numbers down.
  4. Digests. Read the student snapshot and the expected-digest list with the two-consecutive-read rule the loader already enforces; keep the receipts. Any mismatch stops here.
  5. Package. One archive containing: the pinned image reference, the student digest list, the manifest v4 root, the batch (rows plus manifest), the renderer at its admitted commit, the trainer and its launcher, and this sheet. Hash the archive; record it.

The session (one rented GPU, one operator, no other writer)

  1. Rent one instance (A10 24 GB proven; H100 if available), named for this order; arm automatic termination at the 3.5-hour mark before anything else runs. Record instance id, region, start time and the termination readback.
  2. Transfer the package over the authenticated route that worked in C61 (SSH over port 443). Verify the archive hash on the instance. Pull the pinned image by digest only; never by tag.
  3. Load check. Start the container offline (--network none after the pull), with the snapshot and batch mounted read-only. Confirm the loader's verified-read receipts and the tokenizer and pad-row allowances already merged (#497, #498, #509). Any refusal stops the session; no tolerance is added on the instance.
  4. Train. One epoch-mode run: train_adapter.py --rows accepted.jsonl --epochs <1 to 6> --epoch-context-limit <measured> --expected-digests <list> --trusted-digest-root <root> --publication-binding <binding> --report <report.json> with the 4-bit student selected. The trainer's own gates apply unchanged: response-only loss, gradient accumulation 8, learning rate 1e-4, the evaluation at the epoch-1 midpoint and every epoch end, the stop rules of D-M2-39 (stop if the primary metric or any field falls more than 5 points below its best, after two non-improving epoch ends, or at six epochs), checkpoint selection by the exact-item F1 of D-M2-38. Watch the deadline; the trainer stops itself at the limit.
  5. Export. Merge the selected checkpoint onto the bf16 pairing and export the Q4_K_M GGUF with the image's prebuilt llama.cpp, exactly as export-adapter.ps1 does on the host; hash the adapter leaves and the GGUF twice.
  6. Retrieve. Copy report, adapter, GGUF, hashes and the container log back over the same route; verify every hash after the copy.
  7. Teardown. Terminate the instance; confirm with an authenticated instance list showing none; record the usage figure the provider shows.

After the GPU (on the host)

  1. Import the GGUF into LM Studio under a new model name; serve one constrained completion with serve-smoke.ps1 -SingleHost style checks bound to the report; record the response hash.
  2. Score Set A with the unchanged pipeline (build_inputs.py, generate_candidates.py, score_packets.py, two non-author graders: the Claude and Grok pair); record field-level acceptance against the base model's M1 score as the regression baseline.
  3. Run the IFEval and GSM8K regression at the pinned harness revision from the regression freeze (D-M2-30); at most a 3-point drop per task.
  4. Record everything as one decision-log row: pins, batch hashes, epochs run, selected checkpoint, dev metric, Set A result, regression result, rental cost. Then the Director rules on v0.2 or on the teacher change.

Stops

Any of these ends the session and is reported, never worked around: a hash mismatch at any step; a loader refusal; headroom below the stated figure; a missing termination readback; a provider or route failure that would need a second rental in the same session (a second rental is a new order); any instruction to add a tolerance, change a pin, or touch held-out text.
