Construction-only KEP inputs, rule v2

Authority and boundary

WO-R1 is authorized by the owner relay in issue #299, comment 5973258630. This extends licensed KEP preparation with a target-free input artifact. It does not admit training rows, run a model, grade output, or open any held-out set. The target-bearing extraction route and its historical evidence stay unchanged.

The constructor consumes the pinned public Kubernetes enhancements archive, LICENSE, tree and metadata census. It must not invoke construct_rows, initialize HeldOutSet, call a leak validator, access a model transport, or extract archive paths onto disk. Python's tarfile documentation distinguishes regular files and links; the constructor reads only bounded, uniquely named regular members after validating their paths and evidence pins.

Qualification and frozen order

Rule v2 accepts exact metadata statuses implemented and implementable and does not filter by creation date. A positive unique KEP number identifies one source group among status-eligible entries. Duplicate eligible positive identities and conflicting evidence are refused. A replaced/ineligible entry and one implemented entry with the same authenticated number retain two census decisions but only one eligible source group; they do not veto unrelated candidates. The authenticated YAML kep-number, equal to the census ID, is the identity authority. A directory numeric-prefix disagreement receives one explicit DIRECTORY_ID_MISMATCH refusal in the qualification census and aggregate counts; that entry is never accepted, reidentified or silently dropped, and unrelated valid entries may continue. Nonpositive IDs retain their counted refusal when their directory prefix agrees. Before any README read, every census entry (including directory-refused and ineligible entries) must match the number and exact status in its independently pinned kep.yaml bytes and Git blob. Every census decision retains that authenticated number, including ineligible and nonpositive entries; a null number must not erase the audited identity. Untrusted evidence (a hash failure, YAML/census identity or status disagreement, or duplicate eligible positive identity) still refuses the whole run. Metadata is inspected as YAML nodes with the existing PyYAML dependency; no YAML object constructors run. Duplicate top-level keys, merge keys and ambiguous or non-scalar identity fields are refused rather than reinterpreted. All four original support sections must be present and visibly nonempty: Non-Goals, Notes/Constraints/Caveats, Alpha Graduation Criteria, and Test Plan. The (Optional) heading annotation is editorial, not a separate section. Fake headings in comments or code fences do not qualify a source. Comment literals inside fences do not open HTML comments; a real unterminated comment remains invisible through EOF. Optional annotations also normalize the Graduation Criteria parent. Closing heading hashes require preceding whitespace, and the selected H1 title cannot also supply a mapped input section. An inline-comment ambiguity in the first visible H1 refuses the input rather than selecting a later H1. Fence delimiters and their info strings do not make an otherwise empty support section nonempty; actual fenced body text may count.

Inputs also need a genuine first H1 title and a nonempty original Goals section for the objective. Missing input facts are refused, never invented. Context contains the original cited excerpts, with exact half-open Unicode character spans into the verified source. Section names belong to audit metadata, not additional model-input fields. The shared input has only objective, repository, title, and context, as defined by train/prompt_template.py.

The census field sig is a legacy name for the original namespace: validated sig-* and historical provider-* paths remain in their own buckets. No entry is dropped or remapped because its namespace is a provider. Unsafe paths and unrecognized namespace prefixes are refused before status filtering.

Freeze candidate order before reading bodies: lexicographic namespace order, numeric KEP number and path within each bucket, one candidate per bucket each round. The existing sig-round-robin/numeric-id-path/v1 policy identifier is retained with this namespace interpretation. Qualified records keep that rank even when earlier candidates are refused. Qualification is independent of later record clocks. Approximately 130 sources is an estimate, not an output requirement; actual counts and every refusal must reconcile.

Target-free protocol

The new kep-input/v1 artifact is distinct from kep-extraction/v1 and the director training-row schema. A record has disposition: construction_only, source identity, frozen selection rank and digests, source capture and generation times, the shared input, and title/objective/context spans. It has no target, target spans, grade, accepted status, train split, training row ID or model receipt. An exact key contract rejects accidental target-bearing fields.

inputs.jsonl is UTF-8 with LF, one record per usable qualified source in frozen order. Its manifest binds the exact output bytes and each line digest, the archive/commit/LICENSE/tree/census, rule-v2 policy, qualified selection and complete per-candidate census. The census distinguishes metadata candidates, section-qualified sources, usable inputs and refusal reasons.

Evidence and publication

Every source is bound to the archive, its SHA-256 and upstream Git blob. A new v2 policy/order freeze precedes v2 source capture and qualification; historical archive capture remains separate. Each input has its actual generation time. Source spans must reproduce the exact verified text, and chronology cannot be backdated or reversed. Manifest digests must not be cyclic with record timestamps.

Validate the complete artifact before publishing one new destination. Existing outputs are refused without replacement. No usable input means no successful published input artifact. Errors and stdout contain counts and reasons only, never source excerpts. A dry run qualifies and validates without publishing.

The two-file output format is retained. Native publication mechanics are tested on Windows only; other platforms, including POSIX, refuse OUTPUT_PLATFORM_UNQUALIFIED before creating output directories. Dry-run qualification publishes nothing and does not claim publication compatibility. The previous POSIX mkdir/stat/open sequence did not establish newly created directory birth identity and is not a safe fallback.

Before path access, input and output components named heldout (case-insensitive), ending in a dot or space, or containing a tilde followed by a digit are refused. This deliberately rejects ambiguous Win32 and 8.3 spellings rather than guessing their authority. See Microsoft's file and path naming rules. Each acquired native object is additionally checked using GetFinalPathNameByHandleW with normalized DOS names (flags zero) before any content read, child acquisition, or publication write. That handle-derived name must pass the same guard; name-query failure refuses the operation and closes the handle, without a pathname resolver fallback. Existing no-delete-sharing and no-reparse guarantees remain in place.

The existing synthetic constructor suite is registered by tests/test_prepare_kep_inputs.py in ordinary unittest discovery, including the Windows CI shard runner. Its native publication cases execute on Windows; the existing explicit platform skips remain on non-Windows hosts. No workflow or platform configuration is changed.

Existing Windows ancestor identities are captured before acquisition and must equal the acquired objects; pre-acquisition changes refuse publication. Retained CreateFileW directory handles request GENERIC_READ (metadata-only access did not enforce the rename-sharing restriction in the synthetic regression), use BACKUP_SEMANTICS and OPEN_REPARSE_POINT, deliberately omitting FILE_SHARE_DELETE on every ancestor and output, preventing their rename or deletion through the publication window. Reparse points are refused. Handle identity compares both volume serial and the full 128-bit file ID via FILE_ID_INFO, without assuming Python's Windows inode width.

Every new ancestor and output directory is atomically created relative to an already acquired parent by the documented user-mode NtCreateFile. RootDirectory binds the parent object; a single-component name, FILE_CREATE and FILE_DIRECTORY_FILE create one new directory and return its birth handle. The handle requests FILE_LIST_DIRECTORY, FILE_READ_ATTRIBUTES, SYNCHRONIZE and no delete sharing; FILE_SYNCHRONOUS_IO_NONALERT and FILE_OPEN_REPARSE_POINT are used. Success must report FILE_CREATED. There is no pathname mkdir followed by a first snapshot of a possibly substituted object. The returned birth handle already denies rename before its first identity query. An object inserted before creation is refused rather than opened; an unexpected new ancestor is OUTPUT_PATH_RACE, and an occupied output is OUTPUT_EXISTS. Staging files retain handles without write or delete sharing until publication completes. Unsupported native/identity/filesystem APIs fail closed; the actual synthetic Windows test does not qualify other filesystems or hosts.

Files are written exclusively through opened handles, flushed, and installed without replacement using hard links. manifest.json is linked last without replacement. The manifest-presence-only completion rule is retired by Claude's ADOPTED completion-contract ruling in issue #299, comment 5978251273: a foreign actor can insert that filename before the final link, causing refusal but leaving foreign bytes beside the inputs. An exclusive directory handle does not prevent child insertion. Manifest presence alone is therefore not qualified as proof of successful construction. The completion result and external receipt boundary below are ADOPTED by that exact authority. The host consumer implementation has been inspected at the retained revision-3 source pins described below. Actual administrative admission and real-run qualification remain pending; this pass does not release the constructor, claim namespace exclusivity, or establish downstream admission. This does not claim an atomic two-file directory rename, nor protection against an actor authorized to modify file contents after successful publication. An interruption may leave an incomplete reserved directory; later invocation refuses it instead of deleting or replacing it. Cleanup concerns only constructor-owned temporary objects: SetFileInformationByHandle(FileDispositionInfo) marks the still-open owned handle for deletion before it closes. No pathname unlink follows the close; a foreign replacement is preserved. Failure preserves the temporary instead of using a pathname fallback. The final hardlink remains after deletion of the temporary name in the actual Windows regression. Hard-link and handle API failures have no weaker pathname fallback. Protected held-out paths and symlink/reparse artifact/output paths are refused.

Pinned artifact reads are also Windows-qualified only; other platforms refuse ARTIFACT_PLATFORM_UNQUALIFIED. Each ancestor is opened one component at a time relative to an acquired directory handle with NtCreateFile, FILE_OPEN and FILE_OPEN_REPARSE_POINT; reparse attributes are checked before advancing or reading. The leaf is a non-directory object opened without write/delete sharing; the bounded read uses that same held leaf handle. No artifact pathname is reopened after validation, and junctions refuse before reading their targets. The exact byte hash remains mandatory. Dry-run permits an ordinary occupied output directory without creating, replacing or deleting anything there; protected paths and reparse outputs remain refused.

ADOPTED completion result and mandatory external receipt boundary

Only after successful two-file publication does the constructor return and its CLI print one JSON object with protocol: kep-input-completion/v1, completion_status: completed, dry_run: false, inputs_sha256, manifest_sha256, policy_sha256, and the existing aggregate summary fields. The two artifact hashes cover the exact supplied/written bytes, including each final LF. The constructor does not self-hash its source through a mutable pathname. Dry-run explicitly returns completion_status: not_completed, dry_run: true and counts, with no publication hashes. A refused or interrupted publication never returns/prints completed output: the CLI exits nonzero with a refusal. A foreign manifest collision remains a refusal; foreign bytes are not deleted.

This JSON does not authenticate itself. Before ANY real use, the existing Local LLM setup harness writer must implement a consumer gate that verifies an authenticated host receipt from the actual approved constructor invocation. That receipt must bind the trusted constructor code identity, actual argv and approved execution/output root, observed terminal exit 0, the whole strict JSON stdout, and both exact artifact hashes. The host records the actual invocation; a row caller cannot substitute a dictionary, paths, code pins, or receipt. The consumer must require the completed protocol/status and dry_run: false, validate the policy binding and independently compare the actual input and manifest bytes against the receipt's exact hashes before admitting any inputs. Fabricated caller output, exit 0 alone, manifest presence, stale or missing receipts, and changed artifacts cannot admit inputs. A dry-run result cannot be promoted into a publication receipt.

Constructor interface

eval/prepare_kep_inputs.py takes --archive, --tree, --census, --license, --policy, --policy-sha256, and --out; --dry-run publishes nothing. The first four files have immutable production pins in the tool. The policy must be frozen before source reads, contain exactly these keys, and bind the actual new policy bytes through the command's expected SHA-256:

{
  "protocol": "kep-input-selection/v2",
  "repository": "kubernetes/enhancements",
  "commit": "f7be055669b365e9b4ab3905bda6ef385e0c84ca",
  "statuses": ["implemented", "implementable"],
  "creation_date_filter": null,
  "required_sections": ["Non-Goals", "Notes/Constraints/Caveats", "Alpha Graduation Criteria", "Test Plan"],
  "order": "sig-round-robin/numeric-id-path/v1",
  "frozen_at": "<actual explicit UTC time before construction>",
  "authority": "issue299/comment5973258630"
}

The citation binds the declared policy; it is not a signed owner-approval receipt. Source/group identity and external admission still require the normal independent review and recorded work-order gates. Goals and the four supporting sections are context; visibly nonempty Summary and Motivation are included when present. Context spans include the authenticated original role heading; nested Alpha also includes its original Graduation Criteria parent heading. If another child heading occurs between that parent and Alpha (for example Beta before Alpha), the input is explicitly refused as ALPHA_PRECEDING_SIBLING; one continuous Alpha context span must not silently cite the earlier sibling's content. Each section's body is separately required to be genuinely nonempty, so a heading alone cannot qualify it. The objective is still the trimmed Goals body, not its heading. Missing title or Goals are input-usability refusals distinct from section qualification. A zero-usable-input result exits nonzero and prints only its aggregate census counts/reasons. Successful manifests retain every metadata candidate disposition and refusal reason.

Per-record SHA-256 covers the exact JSONL line including its LF. Qualification SHA-256 covers the canonical qualification object embedded in the manifest; qualification includes the frozen-order digest and census but no record generation timestamps, so there is no cyclic record hash. Source capture is the new v2 archive-member read, not a backdated claim about historical capture.

The shared, standard-library prompt_template input helpers and the repository's existing PyYAML dependency are imported; metadata node parsing executes no YAML object constructors. The constructor never imports the target-bearing generator or held-out validator. Literal secret-marker screening is conservative and does not constitute a full secret scan or admission verdict. The authorized host performs remaining scan, review and consumer-binding checks before any model work.

The tool is qualified with synthetic archive/source fixtures only. The eventual authorized host corpus run must recheck all pins before reading public proposal bodies. Existing KEP-2802 extraction and v1 artifacts are preserved.
